Phase 2 — Core Domain Models: complete
What was implemented: Category, the seven-member Question hierarchy (SingleQuestion, MultiQuestion, NumericQuestion, TextQuestion, RankingQuestion, GridQuestion, DerivedVariable), and Codebook — all in core/codebook.py.

Scope decision, stated before I coded it: Variable (the physical-data-column concept from the original class diagram) is deferred to whichever phase actually implements grid/multi expansion (Phase 7), not guessed at here.

A real bug I hit and want to be transparent about, not bury in a diff: the first version of every subclass's __post_init__ used zero-arg super().__post_init__(), which is broken with frozen=True, slots=True dataclass inheritance — @dataclass(slots=True) rebuilds the class via type() after the class body runs, so the __class__ closure cell zero-arg super() relies on still points at the pre-slots class object, not the one self is actually an instance of. It fails with a TypeError at the first instantiation of any subclass, not silently. I caught it because I ran the full test suite before declaring this done, not because I anticipated it — fixed by using explicit super(ClassName, self).__post_init__() in every subclass, verified with an isolated repro before touching all seven. Worth knowing if you write more slotted dataclasses with inheritance later in this codebase.

Design decisions:

All domain objects frozen + kw_only=True (sidesteps the classic dataclass-inheritance "non-default argument follows default" ordering problem entirely) + slots=True (memory-conscious, given large questionnaires may have thousands of category/row objects).
Grid rows are flattened into the Codebook's flat id namespace alongside the grid itself — a row like Q2_1 is independently addressable, since it's a real data column, not hidden metadata.
Derived-variable dependency ordering uses Kahn's algorithm with alphabetical tie-breaking for determinism; validated against a genuine diamond-dependency case (not just a simple chain) to make sure the cycle detector doesn't false-positive on legitimate shared dependencies.
Two new CodebookError leaves added to Phase 1's exception module (InvalidQuestionDefinitionError alongside the already-planned UnknownVariableError) — an anticipated extension per that module's own docstring, not a restructuring.
Tests: 90 passed, 1 skipped (same pre-existing root-permission skip from Phase 1). 52 new tests cover every validation branch per class plus five dedicated Codebook-level tests: duplicate ids (top-level and grid-row-vs-top-level), unknown dependency references, circular dependency (both 2-node and 3-node cycles), the 3-deep chain acceptance criterion from the roadmap, and the diamond-dependency false-positive check.
