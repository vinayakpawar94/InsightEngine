Phase 3 — Data Engine (pandas backend only): complete
What was implemented: data/base.py (RawTable, DataHandle/DataBackend structural protocols), data/csv_loader.py, data/loader.py (format sniffing + load_file), data/backends/pandas_backend.py.

A real bug I hit, not swept under the rug: the first version of PandasDataHandle silently corrupted missing values. RawTable/DataHandle promise None for a missing cell — that's what the CSV loader actually produces — but pandas silently converts None to float('nan') internally for object-dtype columns that mix strings and None. My first test run caught it ('NYC', nan, 'LA' instead of 'NYC', None, 'LA'). Fixed with a _denormalize_missing helper applied on every read path, deliberately scoped to the float-NaN case only — I did not add speculative handling for pd.NaT/pd.NA, since no loader in this codebase produces those dtypes yet, and untested handling for a case that can't occur is exactly the kind of code this project's rules forbid.

Design decisions:

DataHandle/DataBackend are Protocol, not ABC — structural typing so a test fake never needs to inherit from framework code. Proven directly: test_data_base.py and test_loader.py both exercise a pandas-free fake backend satisfying the same protocol pandas does.
CSV loader does no type coercion — every value is str or None. Deciding a column is numeric without a Codebook to check against would mean inventing fragile heuristics; that decision belongs to whichever later phase wires the Data Engine to actual questionnaire metadata.
Default CSV encoding is utf-8-sig, not utf-8 — chosen specifically because of the BOM/encoding pitfalls this exact project has already hit once this conversation, in a different system. Verified with a real BOM-prefixed fixture, not just asserted.
sniff_format recognizes CSV/Excel/JSON/Parquet now (so the enum never needs a breaking change later), but load_file is explicit that only CSV is implemented — asking for Excel raises a clear UnsupportedFormatError, not a placeholder.
Added pandas as a real pyproject.toml dependency (plus pandas-stubs/mypy as dev deps) — it was only ad hoc–installed in the sandbox before this point.
Tests: 134 passed, 1 skipped (same pre-existing Phase 1 root-permission skip). 100% coverage on every Phase 3 module, including a deliberately-constructed csv.field_size_limit() test to exercise the csv.Error branch deterministically rather than guessing at a malformed-CSV byte sequence that may or may not trigger it. mypy --strict clean across all 15 source files.
